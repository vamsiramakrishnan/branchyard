# Command reference

Every command `by help all` lists, with its subcommands and options, as `by`'s own definitions give them. This page is generated by `by man --markdown`; do not edit it by hand: `python3 tools/check.py --fix` rewrites it, and a test fails when it is stale. `by help COMMAND` prints the same text with the command's examples, and [surfaces](surfaces.md) says where each operation is reached outside the command line.

## Global options

These go before or after any command.

| Option | What it does |
|---|---|
| `--remote <URL>` | Run commands on a Branchyard server at URL instead of locally |
| `--token-file <FILE>` | The server's bearer token, on the first line of FILE |
| `--repo <NAME>` | Repository on the server, when it serves several |
| `--ca-file <FILE>` | Also trust this CA certificate for https |
| `--no-notify` | No bell or desktop notification when a branch needs you or ends |

## `by run`

Run a task on a new branch; waits for the turn (--detach returns at once)

```text
by run [OPTIONS] [PROMPT]
```

| Option | What it does |
|---|---|
| `<PROMPT>` | The task for the harness; quote it (with --issue, added to the issue's text) |
| `--detach` | Return as soon as the turn has started, leaving it running in the background; its output goes to a log under .branchyard/detached/ (local mode) |
| `--json` | Print JSON: the branch as `by show --json` prints it once the turn has ended (activity goes to standard error); with --detach, the branch and the log's path |
| `--harness <ID>` | Harness or profile ID (default: claude-code, or routed when there is a [fleet]) |
| `--auto` | Pick the harness from the [fleet] table in branchyard.toml, learning from outcomes, and fail over to the next candidate when a harness fails |
| `--kind <KIND>` | The task's kind (default: inferred from the prompt): bugfix, feature, refactor, review, research, docs, migration, tests, other |
| `--seed <N>` | Seed the router, for a reproducible pick |
| `--issue <REF>` | Take the task from this issue: GitHub's (URL, #N or N, through gh), linear:KEY, jira:KEY, gitlab:GROUP/PROJECT#N, or a Linear, Jira or GitLab URL; a prompt, if given, is added |
| `--pr <N>` | Start from GitHub pull request N's head (fetched with gh and git); by pr then updates it |
| `-n, --name <NAME>` | Branch name (default: a slug of the prompt) |
| `-b, --base <REV>` | Base revision (default: HEAD) |
| `--check <CMD>` | Command that must pass before the branch merges, such as "cargo test": split into words like a shell does, then run directly, not through a shell (use `sh -c "..."` for pipes) |
| `--budget-usd <DOLLARS>` | Stop once the harness's own cost estimate, or on the model gateway its metered cost, exceeds this many dollars |
| `--max-turns <N>` | Stop after N turns |
| `--max-minutes <MINUTES>` | Interrupt the turn after this many minutes (or a duration such as 90s or 2h) |
| `--stall-after <MINUTES>` | Mark the branch stalled after this many minutes with no harness activity (or 90s, 2h, ...) |
| `--stall-action <ACTION>` | What a stall does (one of `notify`, `interrupt`) |
| `-y, --yes` | Grant every tool permission request without asking; the harness may write files and run commands |
| `--ask` | Ask on the terminal for each tool permission request |
| `--permissions <PRESET>` | Answer tool permission requests by a named preset: read-only, edit-worktree, or full (as --yes); see docs/egress.md#permission-presets |
| `--allow-unapproved-tools` | Run a profile that does not route tool permission requests to Branchyard (Antigravity, Pi, Amp); its tools run under the harness's own configuration |
| `--deny <TOOL,TOOL,...>` | Tools the harness is denied outright, before any permission answer, --yes included; a trailing * matches a prefix. Stored with the branch: later sends and every child it delegates to keep them, as with by spawn --deny. Repeatable |
| `--isolated <BOOL>` | Private HOME, not a sandbox; the harness is then usually not logged in (one of `true`, `false`) |
| `--command <CMD>` | Launch this instead of the profile's executable, for development and testing |
| `--provider <PROVIDER>` | Where the harness runs: local, microsandbox, substrate or recipe:NAME (default: local, or the branch's own) |
| `--pass-env <NAME,NAME,...>` | Variables to copy into the sandbox, such as API keys; nothing else is |
| `--image <REF>` | OCI image with the harness installed |
| `--cpus <N>` | Virtual CPUs for the sandbox |
| `--memory <MIB>` | Sandbox memory in MiB |
| `--live-branch` | Use the SDK's pause, live branching and full snapshots (unqualified; needs KVM) |
| `--substrate-endpoint <URL>` | Agent Substrate Control API, https://HOST:PORT |
| `--substrate-router <URL>` | Router base URL; requests identify the actor with its routing header |
| `--substrate-template <NAME>` | Actor template that runs branchyard-bridge and the harness |
| `--substrate-key <FILE>` | Bridge signing key from `branchyard-bridge keygen` |
| `--substrate-api-token-file <FILE>` | File holding the Control bearer token, reread for every request |
| `--substrate-server-name <NAME>` | Verified TLS service name for Control, including port-forwards |
| `--substrate-egress <SUBSTRATE_EGRESS>` | Actor egress policy (default: deny); use --substrate-allow-host for an allowlist (one of `deny`, `unrestricted`) |
| `--substrate-allow-host <HOST>` | DNS host the actor may reach; repeat for more hosts, *. matches one label |
| `--substrate-atespace <NAME>` | Atespace for the actors (default: default) |
| `--substrate-workdir <PATH>` | Where the worktree is copied in the actor (default: /workspace) |
| `--substrate-home <PATH>` | The harness's HOME in the actor (default: /branchyard/home) |
| `--substrate-ca <FILE>` | PEM authorities for the TLS Control API, and the router |
| `--substrate-client-cert <FILE>` | PEM client certificate for the Control API, mutual TLS |
| `--substrate-client-key <FILE>` | PEM key of --substrate-client-cert |
| `--substrate-router-ca <FILE>` | PEM authorities for the TLS router, if not --substrate-ca |
| `--substrate-insecure` | Allow http:// or ws:// to hosts other than loopback |
| `--recipe-workdir <PATH>` | Where the worktree is copied on the machine (default: /tmp/branchyard/<branch>-<hash>/workspace) |
| `--recipe-home <PATH>` | The harness's HOME on the machine (default: beside the workdir) |
| `--keep-sandbox <WHAT>` | Between turns: destroy the sandbox (default) or pause it for the next turn |
| `--sandbox-snapshots <N>` | Checkpoints that also keep a provider snapshot, with a kept sandbox (default 3) |
| `--max-paused <N>` | Kept sandboxes of this provider in the repository before the least recently used is destroyed (default 4) |
| `--max-kept-minutes <N>` | Minutes a kept sandbox may go unused before it is destroyed instead of resumed (default: never) |
| `--require-label <LABEL>` | With --remote: only a worker carrying this label runs it (repeatable) |
| `--priority <N>` | With --remote: the operation's priority, -10 to 10 (default 0, or a spawned child's parent's); higher runs first |
| `--no-preflight` | Skip the check, before any branch is created, that the harness is installed and not verified logged out (it is not made for --command or a routed run) |
| `--delegate <DEPTH>` | Let the harness create child branches through Branchyard's MCP tools, DEPTH levels deep (default 1) |
| `--allow-delegation` | Allow the harness's own by commands that act as its branch (spawn, inspect, send, wait, discard, artifact, ask, ...; see docs/delegation.md) without asking; nothing else |
| `--no-wake` | Do not start the harness's next turn on its own when its turn ends while its children run and they then settle |
| `--secret <NAME[=VAR|=@FILE]>` | A credential for the harness, such as ANTHROPIC_API_KEY, from the variable of that name, VAR, or FILE; written only into its private home (--isolated or a sandbox). Repeatable |
| `--auth <METHOD>` | The authentication method when the secrets allow several: api-key, auth-token, oauth-token, auth-file, vertex-ai |
| `--mcp <NAME=COMMAND|NAME=URL>` | An MCP server for the harness: NAME=COMMAND starts a stdio server, COMMAND an absolute path with its arguments; NAME=https://URL connects to a streamable HTTP server where the harness can (Claude Code, ACP agents that advertise it). Repeatable |
| `--mcp-header <NAME:HEADER=VAR|@FILE>` | A header for an HTTP --mcp server, its value read each turn from the variable VAR or the file @FILE and never stored, as a --secret is (so it needs --isolated or a sandbox), such as 'search:Authorization=@/run/search-auth'. Repeatable |
| `--instructions <FILE>` | Standing instructions for the harness, read from FILE |
| `--model <NAME>` | The model, or a size alias (small, medium, large, extra-large) where the harness defines one |
| `--effort <LEVEL>` | Reasoning effort: low, medium, high, xhigh, or 0-100 |
| `--telemetry <URL|off>` | Send the harness's OpenTelemetry to this OTLP/gRPC collector, or turn it off |
| `--connector <GRANT>` | A connector the harness may call through the gateway (docs/connectors.md): CONNECTOR[@ACCOUNT][:read\|write\|write+confirm[:OP,OP...]], such as github:read or 'github:write:issues.*'; only into its private home (--isolated or a sandbox). Repeatable |
| `--network <open|none|HOSTS>` | The hosts the harness may reach (docs/egress.md): open, none, or rules '[METHOD\|METHOD ]HOST[:PORT][/PATH]' separated by commas, such as 'github.com,*.npmjs.org:443' or 'GET\|HEAD api.github.com/repos/*' (a rule naming a method or path is held to inside the connection) |
| `--network-enforce <MODE>` | Refuse to run where the network policy cannot be enforced (required), or run with the proxy's variables only and say so (best-effort, the default) |
| `--model-gateway <MODELS>` | Call the harness's models through Branchyard's model gateway (docs/model-gateway.md), which holds the provider's key, meters every call and holds the budgets; =MODELS limits it to these models, globs separated by commas, such as 'claude-sonnet-*' |
| `--plan` | Plan first: the first turn runs read-only and proposes a plan, and the branch waits for `by plan approve` (or reject) before anything changes |
| `--goal <TEXT>` | A goal a judge must find evidence of before the branch is done; unmet, it gets follow-up turns with what is missing |
| `--goal-rounds <N>` | Follow-up turns at most for an unmet goal (default 2), within the budget |
| `--goal-judge <ID>` | The goal's judge harness, read-only on a scratch branch (default: the [fleet] entry's goal_judge; without one, the branch's check and a non-empty diff decide) |
| `--goal-judge-command <CMD>` | Launch the goal judge with this instead of its executable, for development and testing |
| `--result-schema <JSON>` | JSON Schema for the structured result using only type, properties, required, additionalProperties, items, enum, const, minimum, maximum, exclusiveMinimum, exclusiveMaximum, minLength, maxLength, pattern, minItems, maxItems, uniqueItems, anyOf, oneOf and annotations such as title and description; anything else is refused. Read accepted results with inspect, wait or compare |
| `--result-schema-file <PATH>` | Read the result schema from this file, or - for standard input |
| `--result-required` | Require a structured result matching the schema |
| `--result-deliverable` | Accept the native final JSON answer as the deliverable; no Git change is needed |
| `--result-artifacts <PATH>` | Collect this worktree-relative output manifest after the provider returns files |
| `--result-artifacts-max-files <COUNT>` | Maximum captured files (default: 32; at most 1024) |
| `--result-artifacts-max-bytes <BYTES>` | Maximum total captured bytes (default: 268435456) |

## `by map`

Run one prompt over a list of items, a branch for each

Every item of the list gets its own branch, and the answers are collected.

```text
by map [OPTIONS] <PROMPT>
       by map <COMMAND>
```

| Option | What it does |
|---|---|
| `<PROMPT>` | The prompt template: {{item}}, {{item.FIELD}} (a path such as {{item.a.0.b}}), {{id}}, {{index}} and {{map}} are replaced for each item |
| `--items <FILE>` | Read the items from this file (- for standard input): JSON lines, a JSON array, CSV with a header, or one item per line, by its extension (default: standard input) |
| `--from-command <CMD>` | Read the items from this shell command's output, run in the repository as you |
| `--input-format <FORMAT>` | How the items are written: jsonl, json, csv or lines (default: the file's extension, else guessed from the first character: [ for json, { for jsonl, else lines) |
| `--schema <FILE>` | Each branch must answer with JSON matching this JSON Schema (a subset; see docs/map.md); without one, an item's result is its last reply's text |
| `--out <FILE>` | Write the results here as each item ends: CSV for a .csv file, else JSON lines |
| `--concurrency <N>` | Branches running at once (default 4) |
| `--retries <N>` | New branches an item gets after its first fails (default 1) |
| `--total-usd <DOLLARS>` | Stop starting items once the map has cost X dollars, across runs (per branch, use --budget-usd) |
| `--reduce <PROMPT>` | Then one more branch, given every result, answers this prompt: the map's summary |
| `--reduce-out <FILE>` | Write the reduce's answer to this file too |
| `--rm` | Remove an item's branches once its answer is recorded (failed items' branches are kept) |
| `--retry-failed` | Run the items that failed in an earlier run again |
| `--harness <ID>` | Harness or profile ID (default: claude-code, or routed when there is a [fleet]) |
| `-n, --name <NAME>` | The map's name, which its branches' names start with (default: a slug of the prompt) |

## Exit status

Every command ends with one of these; `--json` puts the same number in an error's `exit`, and [the error kinds](cli.md#exit-status) say which kind ends with which.

| Status | Meaning |
|---|---|
| 0 | the command did what it was asked |
| 1 | the operation ran and failed: a branch failed, a check failed, a merge conflicted, the branch was busy; also a failure not yet given a kind (`unclassified`), and any kind not listed here |
| 2 | the command line asks for what cannot be: a bad flag or value (clap's own usage errors too), an unknown branch, harness or repository, a name already taken |
| 3 | something around the command must change first: not a repository, a harness (or gh, ssh) not installed, a configuration file that does not load, a server that does not answer or refuses the token, a login only you can do |
| 4 | refused before anything ran: a policy, a delegation envelope, a budget or quota, or a capability the harness lacks |
| 130 | interrupted with Ctrl-C: the shell reports 128 + SIGINT. `by serve` and `by worker` catch it and shut down; `by substrate check --smoke` catches SIGINT and SIGTERM to remove its actor, then reports the cancelled smoke with exit 1 |
